# Debugging Dataform and dbt cyclic dependencies and assertion failures

Diagnostic playbook for troubleshooting DAG compilation errors, circular dependency loops (`Found a cycle in the dependency graph`), and broken data quality assertions in Dataform and dbt-bigquery.

---

## Failure sequence diagram

``` mermaid
sequenceDiagram
    autonumber
    actor Dev as Data Engineer
    participant Compiler as dbt / Dataform Compiler
    participant DAG as DAG Dependency Graph
    participant BQ as BigQuery Engine

    Dev->>Compiler: Compile transformation repository
    Compiler->>DAG: Model 'stg_orders' references 'int_customer_stats'
    Compiler->>DAG: Model 'int_customer_stats' references 'fct_orders'
    Compiler->>DAG: Model 'fct_orders' references 'stg_orders'
    DAG-->>Compiler: Circular Dependency Loop Detected!
    Compiler--xDev: Compilation Failure: Cycle [stg_orders -> int_customer_stats -> fct_orders -> stg_orders]
    Note over BQ: Zero queries dispatched (Failed at compile time)
```

---

## Symptoms and diagnostic signals

| Symptom | Error message | Root cause |
| :--- | :--- | :--- |
| **Cyclic dependency** | `Found a cycle in the dependency graph` / `Circular dependency detected` | Two or more models reference each other directly or via transitive intermediate models |
| **Missing reference** | `Compilation error: Model '...' depends on source '...' which was not found` | Typo in `ref()` or uncommitted source declaration file |
| **Unique key assertion failed** | `Assertion failed: uniqueKey test on column order_id returned 14 rows` | Upstream join explosion (one-to-many join) produced duplicate primary key rows |
| **Null key assertion failed** | `Assertion failed: nonNull test returned non-zero rows` | Source ingestion wrote records with null identifiers |

## Diagnostic commands

### 1. Compiling and locating graph cycles locally

```bash
# In dbt: Compile models and print DAG errors
dbt compile

# In Dataform: Compile SQLX tree and inspect JSON graph
dataform compile --json
```

### 2. Inspecting failing assertion rows in BigQuery

When a Dataform assertion fails, query the assertion view directly:

```sql
-- Query failed rows generated by Dataform assertion
SELECT *
FROM `my_project.dataform_assertions.fact_orders_assertions_uniqueKey_0`
LIMIT 50;
```

In dbt, inspect compiled test SQL under `target/compiled/my_project/tests/`:

```sql
-- dbt unique test compiled query
SELECT
  order_id,
  COUNT(1) AS num_records
FROM `my_project.analytics.fact_orders`
GROUP BY order_id
HAVING COUNT(1) > 1;
```

## Resolution playbook

### 1. Breaking circular dependencies
Isolate base extracts from downstream aggregations into clean layered DAG tiers:

``` mermaid
flowchart TD
    subgraph BrokenGraph["Anti-Pattern: Circular Dependency"]
        A1["stg_orders"] --> B1["int_customer_orders"]
        B1 --> C1["fct_orders"]
        C1 -->|"Accidental back-reference"| A1
    end

    subgraph CleanLayers["Best Practice: Monodirectional Layering"]
        Src["source_raw_orders"] --> Stg["stg_orders (1-to-1 Clean)"]
        Stg --> Int["int_orders_joined (Intermediate Logic)"]
        Int --> Fct["fct_orders (Mart)"]
        Int --> Dim["dim_customers (Mart)"]
    end

    BrokenGraph ~~~ CleanLayers
```

### 2. Resolving duplicate primary keys in incremental models
If upstream joins cause duplicate rows, deduplicate using `ROW_NUMBER()` before the merge step:

```sql
WITH deduplicated_source AS (
  SELECT
    *,
    ROW_NUMBER() OVER (
      PARTITION BY order_id
      ORDER BY updated_at DESC
    ) AS row_num
  FROM {{ source('raw_backend', 'orders') }}
)
SELECT * EXCEPT(row_num)
FROM deduplicated_source
WHERE row_num = 1
```

## Prevention checklist

- [ ] Maintain strict monodirectional DAG flow: `sources &rarr; staging &rarr; intermediate &rarr; marts`.
- [ ] Always run `dbt test` or `dataform test` locally before opening pull requests.
- [ ] Add `uniqueKey` and `nonNull` assertions to every primary key column in staging models.
